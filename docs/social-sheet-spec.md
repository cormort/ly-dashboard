# 臉書整理表規格（立委／議員）

給每日更新試算表的人或 AI（例如 Gemini）看的規格。立委觀測站每天同步時會讀這份試算表，
**格式不符會整份拒收、保留上一版**（寧可舊資料，也不要錯資料），所以欄位名稱與格式請照這份文件。

- 立委分頁：現行格式，匯入程式 `server/normalize.mjs` 的 `normalizeSocial` 已在使用。
- 議員分頁：匯入程式 `normalizeCouncilSocial`（伺服器設好 `LY_COUNCIL_SOCIAL_CSV` 才會讀）。

---

## 共通原則（最重要）

1. **不要編造。** 查不到、看不到貼文（粉專關閉、只給朋友看、被擋），就把「最新貼文日期」與「摘要」**留空**，不要猜、不要填今天的日期。
   - 網站用所有人「最新貼文日期」中最新的一天判斷整理表有沒有在更新（超過 7 天會在畫面上警示）。
     如果把查不到的人都填成今天，警示就失效了，畫面也會誤導人。
2. **日期是那則貼文的發布日期**（臺灣時間），不是你查詢的日期。
3. **摘要要來自那則貼文本身**，用自己的話寫一句重點；不要加評論、不要寫成新聞稿。
4. **粉專網址只在確認是本人時才改。** 要改網址，必須打開確認頁面名稱是本人、而且是本人或其團隊經營的頁面
   （不是後援會、粉絲頁、批評頁、政黨頁、媒體頁）。不確定就保留原網址。
5. **不要刪列、不要改欄位名稱、不要調整欄位順序以外的結構。** 對不到人的列太多（超過 10%）會整份拒收。
6. 一列一位，**每一格都是單行文字**（不要換行）。

---

## 分頁一：立委（現行格式）

每列一位**在職立委**（目前約 113 位）。第一列是表頭，**表頭文字必須一字不差**。

| 欄位（表頭） | 必填 | 格式 | 說明 |
| --- | --- | --- | --- |
| `編號` | 否 | 數字 | 方便人工對照，程式不讀 |
| `姓名` | 是 | 文字 | 立法院登記的姓名；原住民委員可只寫漢名（例：`伍麗華`），程式會自動對 |
| `政黨` | 否 | 文字 | 程式不讀 |
| `選區/類別` | 否 | 文字 | 程式不讀（例：`臺北市第一選區`、`全國不分區`） |
| `臉書專頁名稱` | 否 | 文字 | 粉專上顯示的名稱 |
| `最新貼文日期` | 否 | `YYYY-MM-DD` | 最新一則貼文的發布日（臺灣時間）。Google 試算表自動轉成的 `2026/10/5` 也接受；**其他寫法會被當成空白**（例：`10月5日`、`昨天`）。建議把這欄設成「純文字」格式 |
| `最新貼文主題摘要` | 否 | 文字，建議 60 字內 | 最新一則貼文的重點，一句話 |
| `貼文或粉專連結` | 是 | `https://www.facebook.com/…` | 粉專網址（也接受 `m.facebook.com`）。**不是臉書網址的列會被略過** |
| `Threads連結` | 否 | `https://www.threads.com/@帳號` | 選填欄位；有這欄才會讀（也接受 `threads.net`） |
| `Threads最新貼文日期` | 否 | `YYYY-MM-DD` | 同上 |
| `Threads最新貼文主題摘要` | 否 | 文字 | 同上 |

整份拒收的條件（這時網站會繼續顯示上一版）：

- 缺少 `姓名`、`臉書專頁名稱`、`最新貼文日期`、`最新貼文主題摘要`、`貼文或粉專連結` 任何一欄；
- 資料少於 100 列；
- 姓名對不到在職立委的列超過 10%；
- 帳號數比上次成功同步少超過 20%（避免試算表被截斷時把資料洗掉）。

範例：

```csv
編號,姓名,政黨,選區/類別,臉書專頁名稱,最新貼文日期,最新貼文主題摘要,貼文或粉專連結
1,吳思瑤,民主進步黨,臺北市第一選區,吳思瑤,2026-09-27,堅持正向選舉，不贊成選戰負面操作,https://www.facebook.com/taipeineedyou
2,王世堅,民主進步黨,臺北市第二選區,王世堅,,,https://www.facebook.com/shihchien888/
```

（第 2 列是「查不到最新貼文」的正確寫法：日期與摘要留空，網址保留。）

## 分頁二：議員（新格式）

每列一位**現任直轄市議員**（六都，目前約 360 位）。前幾欄沿用專案裡議員粉專對照表
（`scripts/council-facebook.csv`）的寫法。程式用「直轄市＋姓名」對到現任議員；同一縣市有同名的人時，才用「選區」的編號分辨。

| 欄位（表頭） | 必填 | 格式 | 說明 |
| --- | --- | --- | --- |
| `直轄市` | 是 | `新北市`、`臺北市`、`桃園市`、`臺中市`、`臺南市`、`高雄市` | 用「臺」；寫「台」也會自動轉 |
| `選區` | 是 | `第N選區…` | 開頭是「第＋數字＋選區」，後面可加說明，例：`第1選區（士林、北投）`；原住民選區也一樣，例：`第7選區（平地原住民）` |
| `姓名` | 是 | 文字 | 中選會登記的姓名；原住民議員可只寫漢名（例：`宋雨蓁`），異體字（杰／傑、啓／啟）也對得到 |
| `黨籍` | 否 | 文字 | 程式不讀 |
| `Facebook 粉專網址` | 是 | `https://www.facebook.com/…` | 同立委的規則 |
| `現任狀態` | 否 | `現任`、`現任（議長）`、`現任（遞補）`、`轉任立委`、`病逝`、`解職/停權`… | 離開議會的人保留列、改這欄即可（含「轉任」「病逝」「解職」「停權」的，網站不列為現任） |
| `最新貼文日期` | 否 | `YYYY-MM-DD` | 同立委的規則 |
| `最新貼文主題摘要` | 否 | 文字，建議 60 字內 | 同立委的規則 |

範例：

```csv
直轄市,選區,姓名,黨籍,Facebook 粉專網址,現任狀態,最新貼文日期,最新貼文主題摘要
臺北市,第1選區（士林、北投）,汪志冰,中國國民黨,https://www.facebook.com/tcc9105/,現任,2026-10-04,關心社子島開發進度與居民安置
新北市,第5選區（新莊）,石一佑,民主進步黨,https://www.facebook.com/shihyiyou/,現任（遞補）,,
```

## 試算表的設定

1. 兩個分頁可以放在同一份 Google 試算表，也可以各一份。
2. 共用設定：「知道連結的使用者」→「檢視者」（程式不登入，私人試算表會讀到登入頁而拒收）。
3. 給網站的網址是每個分頁的 **CSV 匯出網址**：
   `https://docs.google.com/spreadsheets/d/<試算表ID>/export?format=csv&gid=<分頁gid>`
   - 立委分頁：伺服器環境變數 `LY_SOCIAL_CSV`（沒設時用專案內建的那份試算表）。
   - 議員分頁：伺服器環境變數 `LY_COUNCIL_SOCIAL_CSV`（沒設就不讀議員分頁，議員粉專網址仍用專案內的對照表）。
4. 網站每天同步一次；改完試算表，最晚隔天會出現在網站上。

## 給 Gemini 的每日指示（可直接貼上）

> 你負責每天更新這份 Google 試算表的「立委」與「議員」兩個分頁。對每一列：
> 1. 打開「貼文或粉專連結」（議員分頁是「Facebook 粉專網址」）那個臉書頁面，找到**最新一則**由本人頁面發布的貼文（略過置頂貼文）。
> 2. 「最新貼文日期」填那則貼文的發布日期，格式 `YYYY-MM-DD`（臺灣時間）；「最新貼文主題摘要」用一句話（60 字內、單行）寫出那則貼文的重點。
> 3. 頁面打不開、看不到貼文、或無法確定哪一則是最新的：**這兩格留空**，不要猜，也不要填今天的日期。
> 4. 不要改姓名、選區、網址與表頭；不要新增或刪除列。如果發現網址明顯不是本人頁面，不要改網址，在試算表最後新增一欄「備註」寫下原因即可。
> 5. 完成後，回報這次有幾列填了日期、幾列留空。

## 議員分頁的匯入

每日同步時讀 `LY_COUNCIL_SOCIAL_CSV`（`server/ingest.mjs` 的 `runCouncilSocialIngest`），整份拒收的條件：

- 缺少 `直轄市`、`選區`、`姓名`、`Facebook 粉專網址` 任何一欄（`現任狀態`、`最新貼文日期`、`最新貼文主題摘要` 選填）；
- 資料少於 200 列；
- 對不到現任議員的列超過 10%（遞補者要先在專案的對照表裡，見 `scripts/council-facebook.csv`）；
- 帳號數比上次成功同步少超過 20%。

讀進來之後：粉專網址以整理表為準（取代專案內對照表的網址）；議員近期動態的臉書欄顯示「最新貼文」，並標出資料截至日，
超過 7 天沒有新日期會提醒（同立委）。
